# 生成器架构

`sdl/*_gen.go` 由 `go run ./cmd/sdlsync -generate`（即 `go generate ./sdl`）产生。`sdlsync` 先把 `SDL_VERSION` 固定的 SDL release 的头文件同步到本地缓存（见下文“头文件来源与版本固定”），再运行下面三层流水线：

```
SDL3 C 头文件
   │  internal/ccfront   （modernc.org/cc/v4，多目标解析并合并）
   ▼
internal/ir              （与目标无关的 C API 描述：类型、布局、枚举值、常量、文档）
   │  internal/bindgen   （命名、类型映射、包装规则，dave/jennifer 输出）
   ▼
sdl/*_gen.go  bind_gen.go  layout_gen_test.go
```

流水线编排在 `internal/gensdl.Run`：`ccfront.Load` → 打印 warnings → 删除旧的 `*_gen.go` / `*_gen_test.go` → `bindgen.Generate` → 可选写 `-skipped` 清单。`cmd/gensdl` 与 `cmd/sdlsync` 都只是它的命令行外壳，前者直接使用本地头文件目录（`-include`，用于实验），后者使用同步下来的 release 头文件。

## 0. 头文件来源与版本固定（`SDL_VERSION`、`cmd/sdlsync`）

- `SDL_VERSION`：仓库根的单行文件，保存规范化的 release 标签（`release-3.4.18`）。`internal/sdlsync.ParseTag` 把 `3.4.18`、`v3.4.18`、`release-3.4.18` 统一成这个形式，`prerelease-*`、`preview-*`、带 `-rc` 等后缀的版本只有 `-allow-prerelease` 才接受。
- 同步（`sdlsync.Syncer`）：下载 `https://github.com/libsdl-org/SDL/archive/refs/tags/<tag>.tar.gz`，经 gzip+tar 流式读取，只把 `include/SDL3/*` 的普通文件写入 `<缓存>/<tag>/include/SDL3/`；`..`、绝对路径、符号链接/硬链接、超大文件（单个 4 MiB、总计 32 MiB）直接报错；先写临时目录，校验通过后 rename，因此缓存条目要么完整要么不存在。`.sync.json` 记录源码包 sha256、文件数、版本和 `SDL_REVISION`。缓存有效时不再下载。
- 校验：`SDL_version.h` 的 `SDL_MAJOR/MINOR/MICRO_VERSION` 必须与标签一致，头文件不少于 60 个（实际约 86 个）。`SDL_REVISION` 取 `SDL_revision.h` 里写死的值；GitHub 的 `archive` 源码包没有写入它，此时由标签与源码包 pax 头里的 commit 推导为 `SDL-<tag>-0-g<sha9>`，与官方发布包里的值相同。
- 可复现：生成文件头为 `Code generated by gensdl from the SDL <版本> headers (<标签>, revision <SDL_REVISION>); DO NOT EDIT.`，不含日期；`SDL_FILE/SDL_LINE/SDL_FUNCTION/SDL_ASSERT_FILE` 这类展开为 `__FILE__` 的宏在 ccfront 中被丢弃，输出不依赖头文件所在路径，也不依赖任何 git 状态（`SDL_revision.h` 属于被排除的头文件，`SDL_REVISION` 不会作为常量生成）。`internal/gensdl` 的测试会重新生成并与仓库内容逐字节比较。
- 流程：`sdlsync -latest -write -generate` 升级；`sdlsync -check` 在临时目录重新生成并与仓库比较，差异以“新增/删除/变化的文件 + 首个不同行”报告；`-print-include` 把头文件目录打印到 stdout 供 `SDL_INCLUDE` 使用。
- CI：`ci.yml` 的 `generated` 任务运行 `go run ./cmd/sdlsync -check`，`test` 任务用 `-print-include` 设置 `SDL_INCLUDE`，并以 `SDL_VERSION` 里的版本安装运行时库，使 `sdl/abi_test.go` 真正执行；`sdl-update.yml` 每周与手动触发时运行 `sdlsync -latest -write -generate`，跑 gofmt/vet/test，`SDL_VERSION` 变化则用 `peter-evans/create-pull-request` 开 PR。

## 1. ccfront：C 头文件前端

目标是在没有 C 编译器、没有 SDK 的机器上也能生成（CI 可在任何系统上运行）。

- **内嵌数据**（`internal/ccfront/data`，`//go:embed`）：
  - `predef/<triple>.h`：用 `clang --target=<triple> -dM -E` 预先抓取的预定义宏，每个目标一份（`arm64-apple-darwin`、`x86_64-unknown-linux-gnu`、`x86_64-pc-windows-msvc`，另有 i386 linux）。`Load` 把它作为 `<predefined>` 源文件喂给 cc/v4，从而决定 `#ifdef __APPLE__`、`_WIN32` 等分支。
  - `stubs/`、`stubs_win/`：最小化的 libc 桩头文件（`stdint.h`、`stddef.h`、`stdbool.h`、`stdarg.h`、`wchar.h`、`string.h`…，Windows 版另有 `sal.h` 等空头文件）。SDL 头文件 `#include` 它们时只需要类型定义，不需要真实实现。
  - Windows 目标额外追加 `__cdecl`、`__stdcall`、`__declspec(x)` 等为空的宏。
  - 运行时先把 `data` 解压到临时目录，再作为 `SysIncludePaths` 传给 cc/v4。
- **入口源码**是一个虚拟的 `umbrella.c`：`#include <SDL3/SDL.h>`、`SDL_main.h`、`SDL_vulkan.h`。
- **多目标合并**（`ccfront.Targets`）：darwin/arm64、linux/amd64、windows/amd64 各解析一次。
  - 第一个目标（darwin/arm64）提供类型布局和常量；
  - 函数按名字合并，每个 `ir.Function.Targets` 记录声明它的 `goos/goarch`（只在部分平台声明的函数，生成的文档里会注明）；
  - 类型布局在目标之间不同则产生 warning。
- **过滤**：`excluded`（`SDL_oldnames.h`、`SDL_egl.h`、`SDL_intrin.h`、`SDL_main_impl.h`、`SDL_begin_code.h`…）、`SDL_opengl*`、`SDL_test*` 不属于 libSDL3 的 ABI，被排除；静态/内联函数、`_` 开头的名字被忽略。
- **常量**：`cc.Config.EvalAllMacros` 让 cc/v4 求值所有对象式宏，整数/浮点/字符串值转成 `ir.Const`（`SDL_LINE/FILE/FUNCTION` 除外）；`SDL_MAJOR/MINOR/MICRO_VERSION` 推出 `API.Version`。
- **文档**（`docs.go`）：取每个声明上方的 doxygen 块，抽出 `\param` 文本（`bindgen` 靠它判断参数是否允许 NULL）。

## 2. ir：中间表示

`internal/ir` 里只有数据结构：`Type`（`Void/Bool/Int/Float/Pointer/Array/Func/Struct/Union/Enum/Named`）、`Record`、`EnumDecl`、`Typedef`、`Function`、`Const`、`API`。关键点是 **ABI 事实由 C 前端算好**：`Type.Size/Align`、`Field.Offset`、枚举值、`Record.Size`。bindgen 不猜布局。聚合与 typedef 节点是共享的，可以按指针比较是否同一声明。

## 3. bindgen：Go 代码生成

### 命名（`names.go`）

- 类型、函数、常量、枚举成员：去掉 `SDL_` 前缀并首字母大写（`SDL_CreateWindow` → `CreateWindow`，`SDL_INIT_VIDEO` → `INIT_VIDEO`）。`Uint32` 之类内建 typedef 直接映射成 Go 内建类型。
- 结构体字段：`snake_case` → `CamelCase`，数字开头加 `F`；重名加 `_`。
- 参数名：Go 关键字或会遮蔽内建标识符的名字加 `_` 后缀（`string_`），空名用 `p<i>`。
- 用 `claim(goName, cName)` 登记，Go 名字冲突时跳过后来者并写入 skipped 清单。
- 文件名：`SDL_video.h` → `video_gen.go`，保持与头文件一一对应。
- 匿名嵌套结构体按 `父名_字段名` 命名。

### 类型映射（`types.go`）

| C | Go |
| --- | --- |
| `bool` | `bool` |
| 整数 | 按宽度与符号取 `int8…uint64`；`char` 是 `byte` |
| `float/double` | `float32/float64` |
| `Uint8…Sint64`、`size_t`、`intptr_t` 等 | 对应 Go 内建类型 |
| `enum` | 具名 Go 整数类型 + `const` 块 |
| 指针 | `*T`；`void *` → `unsafe.Pointer`；`char *` → `*byte`；函数指针 → `uintptr`；未输出的结构体 → `unsafe.Pointer` |
| 数组 | `[N]T` |
| 不透明结构体（`typedef struct X X;`） | `type X struct{}`，句柄是 `*X` |
| 标量 typedef | 具名 Go 类型（`type WindowFlags uint64`） |
| `va_list` | 不支持（记入 skipped） |
| `wchar_t` | `Wchar`（手写，`sdl/wchar*.go`：非 Windows `int32`，Windows `uint16`）；`const wchar_t*` 输入参数在包装函数里为 `string`（空串即 NULL，`wcstrNull`），其余为 `*Wchar` |

### 带类型的常量（`policy.go: constType`）

宏常量默认无类型，但 SDL 的标志位（`SDL_WindowFlags`、`SDL_InitFlags`、`SDL_Keymod`…）都有对应的整数 typedef。`ccfront` 在 `ir.Const` 记录 `#define` 的偏移，并在 `ir.Typedef` 记录 typedef 偏移；若某个整数宏与它之前最近的 typedef 之间（同一头文件）只有预处理指令、注释和空行，就把 typedef 名写入 `Const.After`。`bindgen` 据此输出 `Name TypedefName = value`，条件是：

- 该 typedef 被输出为具名 Go 类型（`Uint32` 等内建 typedef 不算，所以 `SDL_MAX_UINT32` 保持无类型）；
- 底层是整数（枚举、结构体 typedef 不算），值能放进该类型（`SDL_HAPTIC_GAIN` 等超出 `uint16` 的值保持无类型）；
- 常量之间做 `|` 仍然合法，因为同类型常量表达式的结果还是该类型。

`constTypeOverrides` 是人工核对头文件后的例外表：`SDL_WINDOWPOS_*` 是 `int` 坐标，保持无类型；`SDL_PEN_MOUSEID`、`SDL_TOUCH_MOUSEID` 等在头文件里被强转为 `SDL_MouseID`/`SDL_TouchID`；`SDL_BUTTON_*` 显式归入 `MouseButtonFlags`。`gensdl` 会打印被加类型的常量总数。需要把带类型常量赋给结构体里的原始整数字段（如 `HapticPeriodic.Type` 是 `uint16`）时，需要显式转换。

### 函数包装规则（`funcs.go`）

每个 C 函数生成一个未导出的 `var fnXxx func(...)`（原始签名，由 `bindAll` 在加载库后 `register` 绑定）和一个导出的包装函数：

- `const char *` 参数 → `string`，用 `cstr` 转成以 NUL 结尾的拷贝；`\param` 文档里出现 `NULL` 时必须在 `policy.go: nullParams` 里分类（未分类则生成失败）：NULL 只表示默认值的用 `cstrNull`（空串传 NULL，文档加注）；NULL 与空串语义不同的（`distinct`）参数公开类型为 `*string`，用 `cstrPtr`（`nil` → NULL，`sdl.Ptr("")` → 空串）。`nullParams` 条目设 `valueForm` 时另生成 `<Name>Value`（该参数改为普通 `string`），再设 `clearForm` 时生成去掉该参数、传 `nil` 的清除函数（如 `SetAppMetadataPropertyValue` / `ClearAppMetadataProperty`）。`ClearByNullParams` 会列出文档写 "NULL to clear/remove/unset/delete" 却不是 `distinct` 的参数，bindgen 测试用白名单强制逐个评审。
- `char *` / `const char *` 返回 → 拷贝成 `string`（`GoString`，NULL 变 `""`）；`\returns` 提到 NULL 的结果同样必须在 `nullDistinctResults`（NULL 表示“未设置”，额外生成 `<Name>OK` 返回 `(string, bool)`，原函数不变）或 `nullFailureResults`（仅表示失败/无此项，`""` 足够）中分类。`CheckNullPolicy` 会在 `Generate` 和 `internal/bindgen` 测试里校验分类表既不缺项也无过期项；文档里提到 `SDL_free` 的非 const 返回值，拷贝后调用 `Free`。
- 以 `const char *fmt, ...` 结尾的 printf 风格变参函数 → `(format string, args ...any)`，经 `cprintf` 做 `fmt.Sprintf` 并把 `%` 转义成 `%%`，作为字面量交给 SDL；其余变参函数、带 `va_list` 的函数、`SDL_stdinc.h` 里非保留名单（`policy.go` 的 `keptStdinc`）的函数一律跳过，原因写入 skipped。
- 其余参数/返回值直接用映射类型；结构体按值传递交给 purego。
- 只在少于 3 个目标声明的函数，在文档加 “Only declared by the SDL headers for …”。
- 文档转换在 `doc.go`：先按段落预处理（代码块与 Markdown 表格 → 缩进的预格式块，`[文本](Category…)` 链接、`**粗体**`、HTML 实体、行内 `\p \c \a \ref \b \e \em \sa`、行首 `@tag` 还原为纯文本），再按出现顺序输出 `Parameters:` / `Returns:` / `Note:` / `Thread safety:` / `Since:` / `See also:` 段落（`\returns` 之后的正文段落留在原位，不再被提前或缩进成预格式文本），并折叠连续空注释行。
- 文档里的 C 标识符通过 `docNames`（已绑定）和 `Options.HandDir`/输出目录里手写文件的导出名（如 `VERSIONNUM`）改写成 Go 名字；其余 `SDL_` 名字写成带反引号的 C 名字。`checkDocNames` 在生成结束时校验：这些名字必须是被跳过的声明或在 `docAllow` 里，否则生成失败并列出全部违规名字（`SDL_HINT_*` 这类通配前缀、`SDL_xxx.h` 文件名不算）。
- 文档（函数文档或参数文档）里出现 `not copied`、`NoCopy`、`must remain/stay valid`、`keeps a reference` 等表示 SDL 保留指针的措辞，且函数有指针参数时，在文档加 `Keep alive:` 说明（`funcs.go: keepAliveNote`）。`must remain available until … work/task` 且点名某个指针参数（如 `ReadAsyncIO`/`WriteAsyncIO` 的 `ptr`）时，说明改为“该参数在任务完成前必须保持存活且不移动”（`taskBufferParam`，由文档推出，无逐函数表）。名为 `userdata`/`value` 的 void 指针按 `storedPointerNote` 提示；其中名字匹配 `asyncUserdataRe`（异步 IO 函数）的再追加一句指向 `NewUserdataHandle`/`UserdataHandleValue`。`SDL_AsyncIOOutcome` 的 `Buffer`/`Userdata` 字段文档由 `outcomeFieldNotes`（小型字段表）补同样的注记。带非 const 二级指针输出参数且文档要求 `SDL_free` 的函数（`LoadWAV`、`LoadWAV_IO`、`ConvertAudioSamples`）注明缓冲区由 SDL 分配、须 `Free`（`freedBufferNote`）。测试 `TestGeneratedUserdataFunctionsHaveKeepAlive` 检查已提交输出里每个带 `userdata` 指针的函数（同步枚举/移除除外）都有 `Keep alive:` 注记。

### 加载与缺失符号（手写，`sdl/loader*.go`）

`register(fptr, symbol)` 用 `Dlsym`（Windows 用 `syscall.GetProcAddress`）找符号；找不到则安装一个会 panic 并给出明确信息的桩函数，并记录到 `missing`，`Available()` 据此回答。这样用较新 release 头文件生成的绑定也能在较旧的动态库上加载。当加载的库版本恰好等于 `SDL_VERSION` 时，`sdl/abi_test.go` 要求 `allBindings()` 的每个符号都存在（SDL 的 dynapi 表在所有平台导出全部函数），用来发现头文件与库之间的漂移。

### 回调（`decls.go: emitCallback`）

函数指针 typedef 生成 `type Xxx uintptr` 与构造器 `NewXxx(fn func(...)) Xxx`，内部调用 `purego.NewCallback`。参数/返回类型无法映射时跳过构造器。purego 每进程最多约 2000 个回调且不能释放，文档里提示每个回调只创建一次。

### 联合体（`emitUnion`）

联合体输出为 `struct{ data [N]uintN }`，其中 `uintN` 取联合体对齐宽度以保证对齐，再为每个成员生成：

- 标量成员：`Name()` getter 与 `SetName(v)` setter；
- 结构体/联合体/数组成员：`Name()` 返回指向内部存储的指针（别名）。

`sdl.Event` 就是这样：`event.Type()`、`event.Key()`、`event.Window()`…

### 结构体与布局测试

普通结构体按 C 字段顺序输出；某个字段类型不受支持时只降级该字段：指针字段变成 `unsafe.Pointer`，其他类型变成同尺寸同对齐的不透明数组，并记入 skipped；结构体其余字段保持类型化。每个输出的类型都在 `layout_gen_test.go` 里记录期望的 `Sizeof/Alignof` 与每个字段的 `Offsetof`，`TestGeneratedLayout` 把 Go 布局与 cc/v4 算出的 C 布局逐项比对，保证按值/按指针传递时与 C 一致。

### 输出

用 jennifer 构造 AST，`go/format` 格式化，文件头 `Code generated by gensdl from the SDL <version> headers (<tag>, revision <SDL_REVISION>); DO NOT EDIT.`（用 `cmd/gensdl` 直接生成时没有括号部分）。每个头文件一个 `<name>_gen.go`（类型 → 常量 → 函数），外加 `bind_gen.go`（`bindAll` 与 `allBindings`）和 `layout_gen_test.go`。

## 4. 如何扩展

- **新增一类映射**（例如 `wchar_t`）：在 `types.go` 的 `builtinNames` 里映射到手写类型（或从 `unsupportedNames` 移除），并在 `bindFunc` 里加转换规则。`wchar_t` 的宽度随平台而异（ccfront 按 darwin/linux 为 4 字节、windows 为 2 字节），所以 `Wchar` 由带构建标签的手写文件定义；生成的布局只在 `wchar_t` 指向的元素宽度上不同，指针与结构体大小一致，`layout_gen_test.go` 在各平台都成立。
- **保留更多 `SDL_stdinc.h` 函数**：编辑 `policy.go` 的 `keptStdinc` 正则。
- **新增目标平台**：在 `ccfront.Targets` 加一项，并在 `data/predef/` 放对应 triple 的预定义宏（`clang --target=<triple> -dM -E - </dev/null`）；若该平台需要不同的 libc 桩，参照 `stubs_win` 另建目录并在 `translate` 里选择。同时在 `sdl/loader_*.go` 添加库搜索路径。
- **增加包装规则**：在 `funcs.go: bindFunc` 的参数循环里增加新的 `argPlan`（参数类型、原始类型、转换表达式）；返回值同理。
- **排除头文件**：`front.go` 的 `excluded` 与 `headerExcluded`。
- 改完生成器后：`go generate ./sdl`（等价于 `go run ./cmd/sdlsync -generate`；本地头文件实验用 `go run ./cmd/gensdl -include <SDL/include> -out sdl -skipped docs/skipped.txt`），运行 `CGO_ENABLED=0 SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy go test ./...`，并检查 `docs/skipped.txt` 的 diff。

## 手写辅助与使用注意

`*_gen.go` 不可手改，但生成器规则会把所有权、nil 与释放规则写进生成的 doc comment；能由头文件机械推出的辅助（切片/字节/平面/纹理形式、`No<Callback>` 常量、访问器、配方）全部由规则生成。只有无法推出的纯 Go 辅助留在手写文件（见末尾）。以下是调用方需要留意的点。

- **回调 NULL 常量**：生成器为每个回调 typedef（`type XxxCallback uintptr`）同时生成 `const NoXxxCallback XxxCallback = 0`（如 `NoAudioStreamCallback`）表示 NULL 回调，并在类型文档中注明零值即 NULL；名字经 `claim` 登记，冲突会被报告。规则测试见 `internal/bindgen/rules_test.go`。
- **切片形式（生成）**：生成器（`internal/bindgen/slices.go`）对每个 `(const T *ptr, int count)` 输入数组对生成 `<Name>Slice`：指针参数换成 `[]T`，计数由 `len` 推出。匹配条件：指针指向 const 的非 void、非 char 的标量/结构体/枚举，紧随其后的是名为 `count`、`num*`、`n*s` 的 int32 参数；返回值为 void/bool/数值（bool 仅限文档为 “true on success” 者）；跳过可为 NULL 的数组、SDL 会保留的数组、前面紧邻另一个 const 指针（计数可能共享）或带第二个数组对的函数。空/nil 切片不调用 SDL，直接返回 true（bool）或零值；长度超过 `MaxInt32` 时 `SetError` 并返回 false/零值（由生成的 `fitsInt32` 判定）。原始包装器的文档会注明 “对空切片取 `&s[0]` 会 panic”并指向切片形式。例如 `RenderPointsSlice`、`RenderLinesSlice`、`RenderRectsSlice`、`RenderFillRectsSlice`、`FillSurfaceRectsSlice`、`UpdateWindowSurfaceRectsSlice`。 文档标注可为 NULL 的第二个同形输入数组（`RenderGeometry` 的 `indices`/`num_indices`）会成为第二个可为空的切片参数：空切片按 NULL 与计数 0 传入；其他第二数组对仍只保留原始包装。
- **字节切片形式（生成）**：生成器（`internal/bindgen/bytesform.go`）对 `(void *ptr, 长度)` 参数对生成 `<Name>Bytes(其余参数, b []byte)`（名字末尾的 `Data` 会被去掉，如 `PutAudioStreamData` 对应 `PutAudioStreamBytes`，`ReadIO` 对应 `ReadIOBytes`）。匹配条件：指向 void 的指针（const 与否均可）紧随名为 `len`、`size`、`buflen`、`datalen`、`num_bytes` 的 int32 或 size_t 参数；返回值为 void、整数或文档为 “true on success” 的 bool；跳过指针可为 NULL 的参数、带第二个 void 指针的函数、`keepAliveNote` 判定 SDL 会保留缓冲区的函数，以及 `bytesFormExcluded` 中显式排除的函数（`IOFromMem`/`IOFromConstMem` 保存指针，异步 IO 在返回后仍使用缓冲区，`SaveFile*` 对空缓冲区需要写出空文件）。空/nil 切片不调用 SDL，返回 true（bool）或 0；int32 长度超过 `MaxInt32` 时 `SetError` 并返回 false/0（size_t 长度无此限制）。非 const 指针（如 `ReadIO`、`GetAudioStreamData`）原地填充 `b`，返回值是读取的字节数。原始包装的文档注记 “`<Name>Bytes` takes a []byte instead of a pointer and length.”。 长度参数可以是 int32 或 64 位无符号整数，名字含 `length`（存储 API 的 `ReadStorageFile`/`WriteStorageFile`）；`bytesEmptyCalls` 表登记空切片必须照常调用 SDL（传 NULL 与 0）的函数，因为空文件是合法参数。每个字节形式还生成泛型 `<Name>Slice[T Number]`（`PutAudioStreamData` 对应 `PutAudioStreamSlice`），长度为切片字节数；`Number` 是生成的固定大小数值类型约束，不含指针。
- **平面音频切片形式（生成）**：`planar.go` 的 `planarForms` 显式登记 `void **` 平面指针数组 API（头文件无法表达“样本数按平面计、字节数由流格式推出”）。对每个条目生成 `PutAudioStreamPlanarDataSlices(stream, planes [][]byte, numSamples)`：无平面返回 true；`numSamples<0`、流格式不可读、任一非空平面短于 `numSamples*AUDIO_BYTESIZE(源格式)`、平面数超过 `MaxInt32` 均 `SetError` 并返回 false，不调用 SDL；nil/空平面按 C 契约（`SDL_audio.h`：任一声道数组可为 NULL，SDL 为该声道写入静音）以 NULL 传入且不做长度校验；指针数组由生成的 `planarPtrs` 构造。原始包装的文档注记指向该形式。
- **配方（生成）**（`internal/bindgen/recipes.go`）：由多个 SDL 调用组合而成、无法由单函数规则推出的包装，按触发它的 C 函数登记，各自只生成一次。`IOFromBytes(b []byte) *IOStream` 由 `SDL_IOFromConstMem`/`SDL_IOFromMem` 触发（依赖 `IOFromDynamicMem`、`WriteIO`、`SeekIO`、`CloseIO` 与 `IO_SEEK_SET` 都存在）：把 `b` 拷贝进 SDL 动态内存并回到位置 0，空切片、SDL 失败或短写（先 `CloseIO`）返回 nil；拷贝归 SDL，由 `CloseIO` 释放，无需 `runtime.KeepAlive`，而 `IOFromMem`/`IOFromConstMem` 的内存必须在流关闭前保持存活。`LoadWAVBytes(data []byte) (AudioSpec, []byte, error)` 由 `LoadWAV_IO` 这类加载函数触发：形如 `bool f(IOStream *src, bool closeio, T *out..., Uint8 **buf, Uint32 *len)` 且文档要求用 `SDL_free` 释放缓冲区（沿用 `freedStringRe`）。它在 `IOFromBytes` 流上以 `closeio=true` 调用原函数，把缓冲区拷成 Go 切片后 `Free`，out 结构体按值返回；空数据返回生成的固定错误变量 `errLoadWAVEmpty`，其余失败为 `fmt.Errorf("sdl: LoadWAVBytes: %s", GetError())`。原始 `LoadWAV_IO` 的文档注记其缓冲区由 SDL 分配、必须 `Free`。
- **纹理字节形式（生成）**（`internal/bindgen/texture.go`）：纹理缓冲区的大小取决于纹理格式与更新矩形，头文件无法表达，所以由 `textureUpdates` 表显式登记（`SDL_UpdateTexture`、`SDL_UpdateYUVTexture`、`SDL_UpdateNVTexture`），生成 `UpdateTextureBytes`、`UpdateYUVTextureBytes`、`UpdateNVTextureBytes`；参数名与表不符时不生成。每个平面都是 `[]byte`，调用 SDL 前校验：纹理非 nil、pitch 为正、矩形尺寸非负（`rect` 为 nil 即整张纹理）、切片长度不小于 `pitch*(h-1)+w*bytesPerPixel`（YUV 的 U/V 平面为 `(w+1)/2 × (h+1)/2`，NV 的 UV 平面行宽为 `2*((w+1)/2)` 个采样）；YUV/NV 还要求纹理格式分别为 YV12/IYUV 与 NV12/NV21/P010。失败时 `SetError` 并返回 false，不调用 SDL。全部切片为空时是返回 true 的空操作；校验用的纯 Go 辅助（`textureHasFormat`、`textureUpdateRegion`、`textureCheckPlane`、`bytesPtr`）一并生成在 `bind_gen.go`。原始包装的文档注记指针不做边界检查并指向字节形式。 单平面的 `UpdateTextureBytes` 对平面格式（YV12、IYUV、NV12、NV21、P010）同样校验色度平面：SDL 在同一缓冲区的 `h*pitch` 之后继续读取色度，所以切片必须覆盖它们（由生成的 `texturePlanarTail` 计算），否则 `SetError` 并返回 false。
- **异步 IO**：SDL 在调用返回后仍持有 `userdata`，不能传指向 Go 内存的指针；用 `NewUserdataHandle` / `UserdataHandleValue` / `FreeUserdataHandle` 传令牌：令牌是 `SDL_malloc(1)` 得到的唯一 C 堆地址（从不解引用；不能用小整数，否则栈扫描会报 `invalid pointer found on stack`），以该地址为键查表；SDL 不再报告该令牌后须 `FreeUserdataHandle`（释放 C 内存，未知或重复释放为空操作）。需要已加载 libSDL3。`LoadFileAsync` 的结果缓冲区由 SDL 分配，需 `Free`；`ReadAsyncIO`/`WriteAsyncIO` 的缓冲区在操作完成前必须保持存活。`(*AsyncIOOutcome).Bytes()` 由 `countedPtrs` 规则生成（`asyncio_gen.go`），`sdl/extra.go` 只保留用户数据句柄表。
- **返回切片的列表包装函数**：nil 表示 SDL 报告失败（见 `GetError`），非 nil 的空切片表示成功但没有条目。
- **`Log*` 变体**：占位符遵循 Go `fmt` 而不是 C printf（写 `%d`，不要写 `%u`）。
- **应用元数据**：`SetAppMetadataProperty(name, nil)` 清除属性；也可用生成的 `SetAppMetadataPropertyValue` / `ClearAppMetadataProperty`。
- **仍然手写**：`StepUTF8`、`StepBackUTF8`、`UCS4ToUTF8`（纯 Go）、用户数据句柄表（`NewUserdataHandle` 等，`sdl/extra.go`）、`sdl/slices.go`、`sdl/macros.go`、宽字符与 GUID 辅助。`slices_extra.go`、`bytes.go`、`nocallback.go` 已删除。
- **原始指针字段访问器（生成）**：`internal/bindgen/ptrfields.go` 对结构体生成安全视图。`countedPtrs` 表（语义配对，头文件未表达）把指针字段与计数字段配对，生成 `(*Palette).ColorSlice()`、`(*AsyncIOOutcome).Bytes()`（`unsafe.Slice`，不拷贝，nil 接收者/nil 指针/非正计数返回 nil，文档写明内存归 SDL 及失效时机）；`SDL_Event` 联合体各事件成员中的每个 `char *` 字段生成 `<Field>String()`（拷贝，nil 接收者返回 ""），如 `DropEvent.DataString/SourceString`、`TextInputEvent.TextString`。 表项可带 `stride` 字段，长度为 计数×步长：`(*Surface).PixelBytes()` 返回 `Pitch*H` 字节的像素视图，可直接交给 `UpdateTextureBytes`。
